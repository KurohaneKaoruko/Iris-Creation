# 创作路线与验收清单

## 当前阶段：小说与剧本

- 小说维持 `stories/` 和原有任务队列；未标记类型的旧工程按小说打开。
- 剧本以 `scenes/` 中的相对文件路径作为场次标识。标题在文件内编辑，排列顺序单独保存。编排不会重命名场次或重写正文。
- 当前仅导出 Markdown 和 TXT（16 MiB 上限），不是行业排版格式。为了保留素材关联与原稿，应用内不永久删除或重命名场次；若要移出整稿，先备份并关闭作品，再手动把文件移出 `scenes/`。
- 已保存的文件与历史随作品目录移动。未保存草稿暂存在本机 WebView，受端口和浏览器存储影响，不能当作备份。模型停止、报错或断流时，应提示未完成，不能把部分文本直接存入场次。
- 剧本分镜记录写入 `creative/storyboard.json`，镜头以稳定 ID 指向 `scenes/` 相对路径；每次编辑校验磁盘版本并对旧 JSON 保留历史快照。编辑器草稿仅暂存本机 WebView，恢复时沿用原版本基线，冲突不自动覆盖。
- 参考图片须由作者显式选择 PNG/JPEG/WebP 文件（≤10 MiB、≤24 MP），完整解码后生成小型 PNG 预览并复制原图至 `creative/references/`。不会发起 Provider 请求；浏览器仅接收校验后的缩略图。移除镜头/素材关联不删除原稿或源图；缺图与哈希不匹配均保留记录并拒绝错误预览。
- 当前可调整镜头顺序、景别、运镜和规划时长，并导出带相对素材路径的 Markdown 镜头清单。移动/重命名场次后需在分镜编辑器重新关联。复制整个作品目录（包含 `creative/` 与 `.novel/`）后，分镜及素材可随目录恢复。

## 候选验收（使用一次性作品或副本）

1. 新建小说和同名剧本，确认目录不同。打开旧小说，检查章节、资料与会话不串作品。剧本创建场次、调整顺序、修改标题，再重启确认顺序与路径未变。添加关联场次的分镜，修改景别、时长和顺序，核对原稿无变化。
2. 编写多行对白和动作，验证场次标题快开、全文搜索及源行定位。编辑后切场次，分别测试保存、继续编辑和放弃修改。模拟异常退出及外部改稿，恢复草稿时必须仍提示磁盘冲突。模拟磁盘空间与目录权限失败，校验保存失败后原稿、历史与草稿。
3. 用已配置的 Provider 起草、停止、重试、查看结果、存为新场次并润色选区。测试限速和中断，不把残稿当成完成稿。剧本 Agent 可引用未修改的场次和大纲，但不应修改原稿。
4. 导出 Markdown 和 TXT，核对场次顺序、中文和对白段落。重复导出不覆盖旧文件。导入有效/损坏/过大图片，核对原图、预览及错误处理；移除镜头与素材关联后确认原稿和原图仍在。复制整份工程（含 `creative/` 和 `.novel/`），在另一目录重启打开，核对镜头、素材和场次的对应关系。
5. 安装器由 GitHub Actions 构建。正式候选仍需 Windows x64、Apple Silicon macOS 和 Linux 上的安装、升级、启动与稿件恢复检查；见 [rc.5 流程](acceptance-v0.1.1-rc.5.md)，不要把本地浏览器测试视作安装验收。

`scripts/smoke-test.mjs` 用真实本地服务和模拟 Provider 回归工作区隔离、文本写入、版本恢复、导出、流式协议及目录复制，不会向外部模型发送内容。

## 编辑器保存与恢复契约

小说章节和剧本场次使用同一编辑保护流程；本机暂存不是磁盘保存，也不是备份。

| 操作或事件 | 内容与基线 | 离开/恢复语义 |
| --- | --- | --- |
| 开始编辑 | 记录当前文件内容为保存基线 | 只修改编辑草稿，不写工程文件 |
| 输入及快速离开页面 | 输入事件同步保留最新草稿，停顿 700ms 后本机暂存；`beforeunload`、`pagehide` 和编辑器卸载补存最新内容 | 未保存时关闭页面仍有浏览器提示；缓存失败明确提示复制或保存正文，不阻塞内存编辑 |
| 切换文件、会话、关闭作品或取消编辑 | 有未保存修改时只显示一个确认框 | 可继续编辑、保存成功后继续，或明确放弃；保存失败不得执行后续导航 |
| 保存或明确放弃成功 | 成功保存才更新基线；明确放弃清除本机草稿 | 后续卸载不得重新写回已保存或已放弃的旧草稿 |
| 磁盘被修改或恢复草稿 | 保留草稿的原始基线；覆盖仅针对用户已看到的冲突版本 | 再次外部修改必须重新确认，不得将“覆盖”变成无条件写入 |
| 连续切换和异步读取 | 文件读取按请求所属作品和路径处理，过期结果被忽略 | 旧文件的迟到响应不得覆盖当前文件或串写草稿缓存 |

自动化回归位于 `webui/src/features/agent/editor-safety.test.tsx`；真实浏览器异常退出、磁盘空间/权限和安装器验收仍按上方候选清单执行。

## 文件服务安全边界

- 小说保留 `.md`、`.markdown`、`.txt` 正文；内部功能继续读写章节元数据、写作历史、任务队列、缓存和记忆索引，不迁移或删除既有工程文件。
- 普通文件接口不能修改版本控制目录 `.git/`、历史存储 `.novel/.history/`、CLI 快照 `.novel/snapshots/` 和工程身份 `.novel/work.json`；也不能删除/重命名它们的上级受管目录。分镜、参考图与媒体任务文件（`creative/` 受管名）经专用接口管理。
- 相对路径在当前作品根内解析；兼容正反斜杠、`./` 与重复分隔符，拒绝父目录、绝对路径、跨平台盘符、控制字符、尾随点/空格别名和已有的符号链接/重解析目录。文件读写、新建、重命名和删除共用边界校验；目录树、文件引用、质量检查和小说导出不跟随链接。
- 单次普通文本读写上限 16 MiB，UTF-8 多字节文本按字节计；超限拒绝且不改原稿、历史或索引。HTTP 请求总大小仍受 16 MiB 限制（包含 JSON 开销）。参考图片沿用 10 MiB / 24 MP 限制，不改变原图保留策略。

这些检查防止错误路径和已有链接的越界操作，不将外部 CLI 的工作目录声明描述成操作系统级沙箱。恶意本机进程并发替换目录的隔离，需要额外的操作系统级机制。

自动化入口：`services/fs_boundary_tests.rs`、`server/rpc_boundary_tests.rs` 和 `node scripts/smoke-test.mjs`（其中 `scripts/fs-boundary-smoke.mjs` 验证真实 HTTP）。拒绝请求要同时核对正文、历史索引与受管文件未变；Linux 链接检查通过不替代 Windows 重解析点或真实 WebView 验收。

## 版本历史持久化契约

- `.novel/.history/revisions.json` 继续保存 `entries`，快照仍放在 `.novel/.history/snapshots/`，文件名为历史 ID 加源扩展名，不更改章节或场次的稳定路径。
- 记录保留 ID、源相对路径、毫秒时间、原因、非空白字数、Unicode 字符数与首个非空行摘要。新记录增加可选 `content_hash`，值为原始 UTF-8 快照字节的 BLAKE3，用于预览/恢复前校验；CRLF 和空白不被规范化。
- 存量记录没有 `content_hash` 时继续可读、可恢复，不伪造旧记录已经有过完整性校验。新记录的快照缺失、被修改或变成链接时拒绝预览/恢复，不改变正文和历史索引。
- 总索引最多保留最新 800 条，先持久化新索引再删除被剪枝的旧快照；索引保存失败则移除本次新快照，不删除已有快照。删除路径必须仍位于受管快照目录。
- 恢复前保存当前正文为 `restore-backup`，恢复与普通保存共用基线保护；恢复完成后可再选择该备份回退。过期基线在留档/改稿前拒绝。手动留档和快照读取也遵守作品路径、普通文件和 16 MiB 限制。

## 检索与源行定位契约

- 全文检索按 `stories/`、`scenes/`、`concept/`、`outline/` 范围扫描 `.md`/`.markdown`/`.txt`，分批读取并在批间让出主线程；每文件命中上限 20、总命中上限 300，超出截断提示。命中行号按归一化后的真实源行计算（CRLF 与 CR 均按换行计）。
- 结果保留提交时的关键词、大小写与范围：提交后修改输入不改变已渲染结果的高亮；文件在检索后被外部改写、旧词消失时，定位只落到该行且不选中任何无关文字（预览无高亮、编辑器仅移动光标）。
- 预览与目录共用 `markdownBlocks` 解析，所有渲染块携带 `data-source-line`/`data-source-start/end` 源行属性；滚动定位依据这些属性逐行解析，**不按渲染高度或比例猜测**。重复标题锚点自动去重（`-1`、`-2` 后缀），点击第 N 个命中定位到第 N 个真实源行；围栏代码块内的命中照常按源行标高亮，但围栏内的 `#` 不进目录。
- 「编辑此处」把源行命中转换为 textarea 选区；textarea 值的 CRLF 由浏览器归一为 LF，偏移按 LF 文本计算。找不到旧词时只把光标移到该行行首。
- 自动化回归：`webui/src/api/search.test.ts`（纯函数）、`webui/src/features/agent/MarkdownView.test.tsx`（渲染与锚点）、`webui/src/features/agent/FilePreview.test.tsx`（滚动目标按源行属性）、`webui/src/features/agent/editor-safety.test.tsx`（Ctrl+K 检索 → 预览 → 编辑全链路）。

## 创作台媒体服务（已接线）

- `creative.rs`（board 存取，`creative/board.json`，512 KB 上限 + BLAKE3 基线乐观并发）与 `creative_media.rs`（图像/视频生成任务，`creative/jobs/*.json` + `creative/assets/*`）已接入 RPC：`load_creative_board`、`save_creative_board`、`list_creative_media`、`import_creative_image`、`generate_creative_media`、`refresh_creative_media`、`get/save_creative_media_settings`；媒体字节经专用流式端点 `GET /api/creative-media/{id}` 返回（支持单段 Range/206，视频可拖动进度条），不经 16 MiB 的 JSON RPC 通道。
- 任务生命周期：`Submitting`（落盘后未确认）→ `Waiting`（供应商任务号已记录）→ `Ready`（产物经校验落盘）/ `Failed`；跨进程中断的提交标记为 `Interrupted`，不隐式重试。单作品并发 ≤3；图像 ≤24 MB、视频 ≤128 MB、导入图 ≤10 MB/24 MP。
- 边界（不得回退）：媒体密钥经 `secrets` 通道按「服务地址」分键存储（`iris-creative-image/video-<blake3(base)>`），前端只接收“已配置”布尔值；下载仅限同源或 Runway 官方 CloudFront、禁重定向、校验 MP4 `ftyp` 头；服务地址必须 HTTPS（本机回环可用 HTTP），不得含用户名/密码/查询/片段。`refresh` 只在 `Waiting` 状态发起供应商查询，其余状态为本地幂等读。
- 普通文件接口的 `protect_storage` 已覆盖 `creative/board.json`、`creative/jobs/`、`creative/assets/`（与 `storyboard.json`/`references` 一并保护，且不再区分作品类型——小说工程同样拦截）。受管祖先目录（`creative` 及其受管子目录）不可经通用文件命令删除/改名。
- 密钥存储沿用 `secrets.rs`：Windows 使用 DPAPI，macOS/Linux 仅为 Base64 本地文件，**不是**跨平台加密存储。
- 自动化回归：`src-tauri/src/server/rpc_boundary_tests.rs`（保护与往返）、`src-tauri/src/server/mod.rs` 的 `media_endpoint_tests`（流式/Range/越权）、`webui/src/features/agent/media-studio.test.tsx`（设置与表单边界）、`scripts/smoke-test.mjs` 媒体段（fake 供应商全链路）。真实付费模型/网络仅由用户自行验收，不在自动化范围内。
