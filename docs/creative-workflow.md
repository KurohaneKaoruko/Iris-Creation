# 创作路线与验收清单

## 当前阶段：小说与剧本

- 小说维持 `stories/` 和原有任务队列；未标记类型的旧工程按小说打开。
- 剧本以 `scenes/` 中的相对文件路径作为场次标识。标题在文件内编辑，排列顺序单独保存。编排不会重命名场次或重写正文。
- 当前仅导出 Markdown 和 TXT（16 MiB 上限），不是行业排版格式。为了保留素材关联与原稿，应用内不永久删除或重命名场次；若要移出整稿，先备份并关闭作品，再手动把文件移出 `scenes/`。
- 已保存的文件与历史随作品目录移动。未保存草稿暂存在本机 WebView，受端口和浏览器存储影响，不能当作备份。模型停止、报错或断流时，应提示未完成，不能把部分文本直接存入场次。

## 候选验收（使用一次性作品或副本）

1. 新建小说和同名剧本，确认目录不同。打开旧小说，检查章节、资料与会话不串作品。剧本创建场次、调整顺序、修改标题，再重启确认顺序与路径未变。
2. 编写多行对白和动作，验证场次标题快开、全文搜索及源行定位。编辑后切场次，分别测试保存、继续编辑和放弃修改。模拟异常退出及外部改稿，恢复草稿时必须仍提示磁盘冲突。模拟磁盘空间与目录权限失败，校验保存失败后原稿、历史与草稿。
3. 用已配置的 Provider 起草、停止、重试、查看结果、存为新场次并润色选区。测试限速和中断，不把残稿当成完成稿。剧本 Agent 可引用未修改的场次和大纲，但不应修改原稿。
4. 导出 Markdown 和 TXT，核对场次顺序、中文和对白段落。重复导出不覆盖旧文件。复制整份工程（含 `.novel/`），在另一目录打开，核对类型、编排和历史。
5. 安装器由 GitHub Actions 构建。正式候选仍需 Windows x64、Apple Silicon macOS 和 Linux 上的安装、升级、启动与稿件恢复检查；见 [rc.5 流程](acceptance-v0.1.1-rc.5.md)，不要把本地浏览器测试视作安装验收。

`scripts/smoke-test.mjs` 用真实本地服务和模拟 Provider 回归工作区隔离、文本写入、版本恢复、导出、流式协议及目录复制，不会向外部模型发送内容。

## 后续实现顺序

| 阶段 | 交付与验收标准 |
| --- | --- |
| 分镜与素材库 | 从场次编排镜头、景别和时长；统一关联人物、场景和参考图，镜头调整顺序不改原稿，复制工程后关联仍有效。 |
| 图片生成与编辑 | 每项任务显示用哪家模型、上传什么参考素材；先预览再纳入工程。编辑保留源图和版本，先验证失败、取消及断网恢复。 |
| 视频生成 | 先以单镜头的图生视频为起点，记录任务状态与产物，重启后可查询或重试而不重复提交；再做漫剧、短剧的多镜头编排与成片导出。 |
